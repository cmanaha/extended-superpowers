// THE IDEA

Why a flywheel, not a pipeline

A pipeline runs once and forgets. A flywheel stores momentum — each turn makes the next one easier, and the wheel only spins faster.

This loop is built that way. Before any design, a planning session researches and an environment-research phase actually runs a dependency to learn how it really behaves — and harvests the findings into memory. Adversarial review at the spec, plan, and implementation gates turns flaws into recorded corrections. The definition-of-done gate is a ratchet: quality can rise but never silently regress.

All of that lands in the hub at the center. So the next turn doesn't start cold — it starts with verified knowledge of the terrain, the corrections that already bit you, and a definition of done the tooling enforces. The outputs become the fuel. That is the flywheel.

// GET IT

Install

In Claude Code, on any machine. superpowers resolves automatically as a declared dependency.

/plugin marketplace add cmanaha/extended-superpowers
/plugin install extended-superpowers@cmanaha

Self-contained and environment-agnostic: it bundles its own review agents and reads from a generic memory store if one is present — never from anyone's personal setup. Restart Claude Code after installing.
